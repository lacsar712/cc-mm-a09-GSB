# 矿井瓦斯班测台

检查员上报测点甲烷浓度。达到 1% 报警线时，服务端通过网页套接字把这条报警推到已经打开的页面。检查员还可设置高于报警线的危急线（默认 1.5%）：浓度达到危急线状态记为「危急」并进入危急专板，报警线与危急线之间为「报警」，低于报警线为「正常」。页面是手写脚本，没有用组件框架，也没有图表。

危急线改动只影响之后的新上报，不改写历史行的状态原文。

## 端口

| 服务 | 地址 |
|------|------|
| 页面 | http://localhost:3191 |
| 接口 | http://localhost:8191 |
| PostgreSQL | localhost:54391 |

## 账号

| 用户 | 密码 | 权限 |
|------|------|------|
| gasman | gas123456 | 可上报、可设置危急线 |
| viewer | view123456 | 只能看（含危急专板），不能改危急线 |

## 启动

```bash
cd projects/12-mine-methane-shift
docker compose up --build
```

## 验收

1. 用 gasman 登录，列表里回风巷是报警，东翼-12 是正常。
2. 再开一个浏览器窗口同时看列表，上报一个大于等于 1 的测点，两个窗口都会出现新记录。
3. viewer 登录后没有上报表单，也没有保存危急线的表单。
4. 进入顶栏「危急专板」，把危急线设成 1.5：报 1.6 状态为「危急」并进专板；报 1.2 状态仍为「报警」且不进专板。
5. viewer 可以打开危急专板查看，但调 `PUT /api/settings/critical-line` 会返回 403。
6. 把危急线改成别的值（必须高于 1%）只影响之后的新上报，历史行的状态原文不变。
